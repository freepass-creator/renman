## 0. 한 줄 요약

> **홈은 조회 화면이 아니라, 오늘 처리할 업무가 도착해 있는 자리.**
> 왼쪽 **목록**에서 고르고, 오른쪽 **수행창**에서 끝낸다. 수행창은 **수행 | 차량360** 두 탭뿐.
> 큰 글씨 없음 · 카드 없음 · 흰 면과 헤어라인 · 용어는 ERP 표준어.

## 1. 배경

### 1-1. 제품
- 렌터카매니저(렌맨, repo `renman`): 렌터카 운영 ERP. Next.js 15 + TS + Firestore. 화이트라벨(업체 CI 적용) 멀티테넌트
- 사용자: 렌터카 운영사 직원(수납·배차·정비·회수)과 본사(HQ). 하루 종일 목록을 훑고 처리하는 B2B 도구
- 기존 확정 사항(바꾸지 않음): 앱 3개(업무·데이터센터·자료올리기) · 360은 어디서든 대상을 누르면 열리는 상세 · 본문 12px · 원장 행 30px · 신호색 3개 · 모바일도 글씨 안 키움

### 1-2. 왜 갈아엎나
- 지배형 ERP 비전: «데이터가 직원을 부린다» — 직원이 ERP를 조회하는 게 아니라, ERP가 감지→판정→지시하고 직원은 처리
- 현재 갭: 감지·판정은 완성도 높음(리스크 4그룹, 어젠다 4종, 회수 4단계…). **전달 배선이 약함** — 홈이 «문제 목록 조회» 형식이라 사람이 매번 «그래서 뭘 하지»를 번역
- 결론: 홈의 **형식**을 바꾼다. 조회 → 수행

### 1-3. 홈의 정의
- 홈 = 「업무」 앱 = **목록 + 수행창**
- 목록: ERP가 감지한 문제를 **조치 단위**로 번역한 업무의 시간축 목록
- 수행창: 고른 대상(차량)의 **할 것(수행)** 과 **전부(차량360)**. 여기서 완료·접수·연기·기록까지 끝냄
- 원장(데이터센터)은 제대로 돌면 볼 일이 없음. 확인하러 갈 때만

## 2. 핵심 개념·용어

| 개념 | 정의 | 예 |
|---|---|---|
| 업무 | ERP가 문제를 번역한 **조치 한 건**. 대상(차량) + 조치 + 기한 + 담당 + (금액) | 「내용증명 발송 · 31마7702 · D+17 · 박영협 · ₩1,670,000」 |
| 조치 | 업무의 앞머리 동사구. 사람이 실제로 하는 일 | 내용증명 발송 · 반납 받기 · 정기검사 예약 · 입금 확인 · 자금 분류 |
| 목록 | 업무를 **언제 하나**로 묶은 좌측 화면 | 지연 · 오늘 · 이번 주 · 예정 · 완료 |
| 수행창 | 우측(모바일은 다음 페이지). 고른 대상의 360 | 탭 = 수행 · 차량360 |
| 수행 탭 | 이 대상에 **지금 할 것** | 선택 업무 + 같은 차량의 다른 열린 업무 + 빠른 기록 + 최근 이력 3 |
| 차량360 탭 | 이 차량의 **전부**(기존 Vehicle360 상위집합) | 현재 상태 6칸 + 이력 전체 |
| 시간축 | 목록의 1차 묶음 | 지연(빨강) · 오늘(주황) · 이번 주 · 예정(접힘) · 완료(접힘) |
| 사람축 | 세그먼트 필터 | 내 업무 · 미배정 · 전체 |
| 도메인 | 어디 문제인가. 칩 필터 | 미수 · 차량 · 재무 |
| 근거키 | 업무의 자연키 = 문서ID | `auto:{종류}:{대상}:{기한}` 예 `auto:미납:31마7702:2026-07-30` |

**용어 표준(§9)**: 지연·예정·완료·접수·연기·이관·미배정·수행·차량360·업무. 조어(지시함·밀린 것·끝냄·맡기·미루기·넘기기) 금지.

## 3. 정보구조(IA)

```

 └ 데이터센터 = 원장 모음(자산·계약·자금·업무 …)  ※ 본 문서 범위 밖
```

- 앱 이름 「업무」는 제안(확정 IA는 「업무조회」). 조회가 아니라 수행이라 「업무」 권함 → §12

- 「＋ 기록」= 단건 기록(⌘K, QuickInput). 파일은 「자료올리기」. 역할 중복 없음

   - 행동 28h: 담당 있음 → `[✓ 완료 잉크] [연기 ▾ 아웃라인] 이관(ghost)` / 미배정 → `[접수 잉크] [연기 ▾] 담당 지정` / 완료됨 → 「✓ 오늘 완료 · 담당」 초록. 우측 kbd 힌트 E S A
   - 빠른 기록 30h 아웃라인 입력: 「＋ 기록」 + 우측 칩 통화 · 입금 · 문자 · 메모 (누르면 해당 유형 입력)
2. **이 차량의 다른 업무 n** — 같은 대상의 열린 업무 행(조치 · 금액 · 기한 · 담당, 30h). 클릭 = 그 업무로 교체
3. **최근 이력** 3줄(일자 · 구분 · 내용 · 금액) + 「전체 → 차량360」
4. 차량 없는 건(자금 분류): 조치 블록 아래 **미연결 입금 표**(일자 · 계좌 · 입금자 → 후보 계약 · 금액)

### 4-9. 차량360 탭
1. **현재 상태 6칸** 3×2 그리드(헤어라인 구분, 카드 아님): 계약 · 미수 · 차량 · 보험 · 금융 · 고객 — **금융과 보험은 절대 합치지 않음**. 각 칸 = 라벨 10.5 / 값1 12/600 / 값2 11 sub. 미수 값은 빨강. 미수는 **건수와 금액** 함께
2. **이력** 전체(28h, 열 헤더 일자 · 구분 · 내용 · 금액 · 기록): 통화·문자·통보·입금·청구·정비·GPS·계약·상담… 시간 역순
3. 실제 구현은 기존 Vehicle360(`lib/detail-sections.ts` 전체 섹션 + history)을 이 폭에 맞춰 렌더. 별도 페이지 아님

### 4-10. 하단바(목록 30h) — `↑↓ 이동 · E 완료 · A 접수 · S 연기 ………… n건`
### 4-11. 토스트 — 잉크 배경 흰 글씨 12px, 좌하단, 1.8s: 「✓ 완료 — 31마7702 내용증명 발송」 · 「접수 — … · 담당 박영협」 · 「연기 — … · 2주 후」

## 7. 업무 규칙(비즈니스 룰)

1. **섹션 판정은 dday 하나**: 미납(회수 단계 업무) → 항상 지연 · dday<0 → 지연 · 0 → 오늘 · 1~7 → 이번 주 · >7 → 예정
2. **조치 문장 = 코드의 action 매핑** (기존 `lib/home-problems.ts` `ACTION_BY_KIND` · `ACTION_BY_COLLECTION_STAGE`):
   - 만기경과 → 반납 받기 · 만기임박 → 반납 안내 · 인도예정 → 인도 처리 · 검사만기 → 정기검사 예약 · 보험만기 → 보험 갱신 · 세금 만기 → 자동차세 납부 · 과태료 기한 → 과태료 납부 · 서류미첨부 → 등록증 올리기 · 자금미분류 → 자금 분류 · 배차충돌 → 배차 기간 조정 · 휴차 → 가동 계획 세우기 · 사고 → 사고 처리
   - 미수 회수 단계 → 회수대기: 입금 확인 · 경고: 연체 통보 · 시동제어: 시동 제어 · 차량회수: 차량 회수 · 내용증명: 내용증명 발송 · 채권화: 법적조치·채권화 (경고 1일 · 시동제어 3일 · 내용증명 10일 · 채권화 30일)
3. **담당**: 같은 회사·차량의 열린 work_item 담당자. 없으면 미배정(주황). 자동배정은 미구현(후속)
4. **지연 실체화**(`docs/PLAN-work-autogen.md`): 목록의 제안행은 계산값. 완료·접수·연기·이관을 누를 때만 work_item으로 저장. 근거키 `auto:{종류}:{대상}:{기한}` = 문서ID → 중복 구조적으로 불가. 연기는 같은 문서의 기한만 이동. 근거 소멸 시 자동 종결 안 함(감사 흔적)
5. **완료 · 오늘** = 오늘 완료된 work_item. 하루의 진행이 보여야 피드백이 닫힘
5-1. **수행 절차**(v3.1): 조치 종류별 템플릿(work_item.steps). 절차 있는 조치는 전 항목 체크 시 완료 가능. 체크 상태는 work_item에 저장(감사)
6. **미수 표기**: 건수와 금액 함께. 빨강은 미수 금액과 지연 기한에만. 과태료·세금 등 지출 금액은 잉크
7. **회사 스코프**: 전체 회사일 때 행에 회사 태그(JPK · 웰릭스 …). 단일 회사면 생략
8. **원장 표기 규칙 승계**: 한 칸에 원자 하나(D-day와 날짜를 한 칸에 붙이지 않음) · 세부 섹션은 `detail-sections` 사전에서 고름 · 금융/보험 분리

## 13. 여러 AI로 구체화하는 프로토콜

### 13-1. 원칙
- **이 SPEC이 정본**. 어떤 AI의 산출물도 SPEC §번호를 지정해 «어디를 바꾸자»로 제안. 조각 임기응변 금지 — 관련 요소 전부를 읽고 설계표로 한 번에
- 확정 사항(§1-1)·금지 목록(§8-5)·용어(§9)는 어기지 않음. 어길 이유가 있으면 «변경 제안»으로 분리해 제출
- 산출물은 실데이터 없이(가공 데이터), 규모감만 실제

### 13-2. 역할 분담 예시
| 역할 | 주는 것 | 받을 것 |
|---|---|---|
| 시각 탐색 AI | SPEC §4·§5·§8 + 목업 링크 | 같은 구조·같은 토큰으로 대안 시안 2~3(다르게 할 곳만 명시) |
| 카피 AI | §2·§7·§9 | 조치 문장·사유 문장 템플릿(도메인별) · 토스트·빈 상태·오류 문구 |
| 컴포넌트 AI | §8-4 + `components/ui` 현황 | React 컴포넌트 규격서(props·상태·키보드·a11y) — 코드는 Cursor |
| 모바일 AI | §5·§6 | 페이지 전환·제스처·바텀시트 vs 페이지 판단 · 저장 후 반영 흐름 |
| 검수 AI | SPEC 전체 + 산출물 | §8-5 금지 위반 · 용어 위반 · 데이터 손롤 집계 · 한 칸 두 원자 지적 |
| 구현(Cursor) | SPEC + §10 | 브랜치 작업. `npx tsc --noEmit` + `curl localhost:6006/ 200`. `npm run build` 금지 |
