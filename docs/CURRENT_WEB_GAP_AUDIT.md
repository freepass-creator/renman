# 현재 웹 ERP 기능·UI 대조

기준: 자료 투입 → 자동 연결·저장 → 미완료 유지 → 다음 행동 제시.

| 주 화면 | 현재 강점 | 핵심 결손 | 목표 UI 규격 |
|---|---|---|---|
| 대시보드 | 운영 스냅샷·KPI·리스크 연결 | 자료 처리현황과 담당 업무 우선순위가 분리됨 | 요약 → 오늘 처리 → 경과 위험 |
| 운영현황 | 차량·계약·미수 결합 | 조회 전용임이 불명확하고 상세 행동 연결이 약함 | 공통 원장 표 + 동일 상세패널 |
| 리스크관리 | 파생 위험을 한 목록으로 집계 | 원본자료·해소조건·담당업무 추적 부족 | 상태·대상·근거·기한·담당·해소조건 |
| 업무관리 | 업무·이력·과태료·수집함 통합 | 분류/실행/배정 상태가 혼재 | 3축 상태 + 연속 상세편집 |
| 자금일보 | 수납 자동매칭·CMS | 원본 엑셀과 거래·매칭 결과 계보가 분리됨 | 원본 → 거래 → 매칭 → 미수 반영 |
| 데이터센터 | 엔티티 스키마·저장 파이프라인 | 엔티티 선선택, 일반 자동분류·처리 큐 없음 | 통합 드롭존 + 처리현황 + 분석 상세 |
| 자산관리 | 등록증 OCR·상세 데이터 | 값의 출처와 후속업무가 약함 | 공통 원장 + 출처 있는 상세패널 |
| 계약관리 | 기간·수납·리스크 계산 | 계약서 업로드부터 계약 생성까지 흐름이 분리됨 | 계약·수납·서류·다음 행동 통합 |
| 자금관리 | 계좌/거래 조회와 분류 | 계좌 엑셀 투입과 결과 확인 문맥이 다름 | 투입 출처·분류·매칭 상태 |
| 경영관리 | 관리 마스터 통합 | 마스터별 생성·상세 규격 편차 | 동일 탭·표·상세·생성패널 |

## 즉시 통일할 공통 규격

1. 주 화면: 제목·설명 → 회사/검색/기간/세부필터 → 상태요약 → 보기/생성.
2. 원장 행: 회사 → 식별자 → 대상명 → 분류 → 상태 → 핵심 수치.
3. 상세패널: 신원 → 현재상태 → 다음 행동 → 핵심정보 → 연결자료 → 변경이력.
4. 생성패널: 최소입력으로 먼저 생성 → 추가정보는 접힘 → 같은 상세에서 계속 수정.
5. 처리상태: 분석중·자동반영·확인필요·미분류·중복·오류·처리완료.
6. 업무상태: 분류상태·실행상태·배정상태를 분리.
7. 빈 상태: 데이터 없음, 필터 결과 없음, 조회 실패를 구분.
8. 행동명: 생성·저장·연결·해제·완료·재개방을 같은 의미로만 사용.

## 분리 화면 판단

- `/inbox`: 데이터센터의 미분류·현장수집 큐로 편입 대상.
- `/ingest/bulk`: 데이터센터의 다중 문서 분석 단계로 편입 대상.
- `/penalty/upload`: 전용 분석기는 유지하되 데이터센터 처리 건에서 진입.
- `/list/[entity]`: 운영 화면이 아닌 원시 데이터 점검용으로 제한.
- `/dev/*`: 운영 내비게이션과 시각적으로 분리하고 본사 권한에서만 노출.
- `/receivables`, `/dispatch`, `/repair`, `/integrity`: 고유 처리 로직은 유지하되 공통 상태·상세 문법 적용.

## 구현 우선순위

1. 데이터센터 명칭·처리상태·상세 문법 통일.
2. 통합 투입 건 모델과 원본 계보.
3. 계좌 엑셀 → 거래원장 → 수납매칭 완주.
4. 등록증 → 차량원장 → 검사/불일치 업무 완주.
5. 계약서 → 계약/고객/차량 → 수납/반납/누락 업무 완주.
6. 업무의 불완전 생성·계속수정·완료·재개방.
7. 활성 웹 화면의 툴바·상태·행·상세 패널 대조.
