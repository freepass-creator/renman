### 4-2. P0-2 설계 (2026-08-05 밤, 윈도우 재설치 직전 스냅샷 — 근거 보존)

- 대상: `app/api/entities/[entity]/route.ts` POST(L83~) — 현재 `batch.set`(L137) 덮어쓰기.
- **확정한 사실**: 클라 `lib/store.ts save()`(L195~)는 자연키 dedup(`seen`)으로 **기존 문서를 절대 다시 보내지 않는다**(존재하면 duplicates++). update는 별도 메서드(L353·418 `setDoc merge`, 클라 SDK 직행 — rules가 지배). 즉 이 라우트는 순수 «생성/임포트» 경로.
- **따라서 구현**: MONEY_ENTITIES(bank_tx·card_tx)만 create-only — `db.getAll(refs)` 선검사 → 존재 시 409(어떤 ID가 충돌인지 반환) + `batch.set`→`batch.create`(경합 이중방어). 비-자금 엔티티는 기존 set 유지(범위 밖). 기존 문서 존재 시 마감월 txDate 검사(L128~135)는 자금에선 409로 대체되어 자연 소멸.
- 페어: 클라 매칭 필드 가변·원자 필드 불변은 **rules `moneySourceImmutable()`**(순위 5)와 클라 `immutable-money` 가드가 담당 — create-only와 3중 구조.
