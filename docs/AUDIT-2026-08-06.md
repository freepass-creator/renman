## 0. 결론 먼저

오픈 자체를 막는 건 **없다**. 자금 등록 → 자금일보 → 자산등록 → 운영현황은 돈다.
다만 **«등록만 되고 안 물린 것»이 3개** 있고, 이건 쓰다 보면 반드시 걸린다.

| 급 | 무엇 | 왜 급한가 |
|---|---|---|
| 🔴 1 | 자금 채널 매칭 미배선 | 카드·CMS·단말기를 등록해도 **거래가 회사에 안 붙는다**. 미배정만 쌓인다 |
| 🔴 2 | 타입이 두 벌 (내 잘못) | `payments/types/company.ts` 와 `company-master.ts` 가 같은 걸 두 번 정의 |
| 🟡 3 | 사업자등록증 OCR이 `/admin` 에만 | 그래서 `/admin` 을 못 없앤다. 법인 등록 동선이 두 갈래 |

## 1. 🔴 자금 채널 — 타입은 있는데 **아무도 안 쓴다**

`lib/payments/types/company.ts` 는 jpkerp5 모델을 **그대로 이식해 둔 파일**이다.
`BankAccount` · `CorporateCard`(cardLast4) · `AutoTransferChannel`(cmsId) · `CardTerminalChannel`(terminalId).
`lib/payments/types/banking.ts:152-156` 에는 거래 쪽 대응 필드까지 주석으로 «어디와 매칭되는지» 적혀 있다.

**그런데 이 파일을 import 하는 곳이 0곳이다.** 타입만 옮기고 배선을 안 했다.

그래서 지금 이렇다:
- 카드 거래를 올려도 `cardLast4` 로 회사를 찾는 코드가 없다 → 미배정
- CMS 입금도 `cmsId` 매칭 없음 → 미배정
- 단말기 매출도 `terminalId` 매칭 없음 → 미배정

**해야 할 일**: 업로드 파이프라인에 «채널 → 회사» 해석기 하나.
`resolveCompanyByChannel({cardLast4?, cmsId?, terminalId?, accountNo?}) → companyId | null`
이게 SSOT 가 되고, 못 찾으면 미배정으로 두되 **«이 채널 등록할까요»를 띄운다**(아래 §5).

## 2. 🔴 타입 두 벌 — 2026-08-06 내가 만든 것

오늘 `lib/company-master.ts` 에 `CorporateCard`/`AutoTransfer`/`CardTerminal` 을 새로 정의했다.
`payments/types/company.ts` 에 **이미 같은 게 있는 줄 모르고** 만들었다. 리포 원칙(공용 원자·두 벌 금지) 위반이다.

**해야 할 일**: `payments/types/company.ts` 를 타입 SSOT 로 두고 `company-master.ts` 는 재수출만.
필드명이 살짝 다르다(`accountNo`↔`accountNumber`, `nickname`↔`alias`) — **합칠 때 이름을 하나로 정해야** 한다.
지금 저장된 데이터가 없으니 **지금이 합치기 제일 싼 시점**이다.

## 3. 🟡 `/admin` 을 못 없앤 이유 = OCR

`components/CompanyRegistry.tsx` 안에만 사업자등록증 OCR 이 있다.
경영관리 법인 패널(§4-11)은 다 옮겼는데 **이것만 남아서** `/admin` 이 살아 있다.
결과: 법인 등록 동선이 «경영관리에서 만들기» / «/admin 에서 등록증 올리기» 두 갈래다.

**해야 할 일**: 문서 섹션 업로드에 OCR 을 물린다(종류=사업자등록증이면 `business_reg` 로 추출 →
상호·사업자번호·대표·주소 자동 채움). 되면 `/admin` 삭제 + 설정 메뉴 링크 3곳 정리.

## 4. 규격 위반 — 기계적으로 잡힌 것

### 4-1. 금지 데코(`ObjCard`/`Metric`/`Cards`) — **20개 파일**

`VEHICLE360-SPEC §1` 은 카드·지표를 폐기하고 KV/표로 통일하라고 확정했다. 차량360·경영관리는 끝냈고 나머지가 남았다.

```
contract-history · dispatch · financials · inbox · insurance/[id] · integrity
list/[entity] · list/[entity]/[id] · m/vehicle/[plate] · manage · pnl · search · vat
Customer360 · MobilePage · CarPanels · HistoryPanels · StatusPanel  (+dev/sample 2개는 제외 가능)
```

⚠ **한꺼번에 하지 말 것.** 화면마다 «무엇이 KV 이고 무엇이 표인가»가 다르다.
차량360처럼 **화면 하나씩, 설계표 먼저** 잡고 간다(사장님 확정: 조각 전환 금지).

### 4-2. `window.alert` 손롤 — 3곳

`components/ui/confirm.tsx` 가 «window.confirm/prompt 금지, 이걸로 통일»이라고 못박았는데 alert 가 남았다.

| 파일 | 줄 |
|---|---|
| `components/QuickLogForm.tsx` | 42 |
| `components/WorkForm.tsx` | 145 |
| `components/StaffConsole.tsx` | 30 |

→ `toastError` 로 교체. 셋 다 한 줄짜리라 위험 없음. **제일 싼 정리.**

### 4-3. 표 «틀고정» — 결정이 없다

`excel-sheet--fit` 이 화면이 좁아지면 열을 숨겨서(`p4→p3→p2`) 폭을 맞춘다.
그래서 **가로 스크롤이 안 생기고**, `pin:true` 가 걸려 있어도 발동할 상황이 없다.
사장님이 «틀고정 없어»라고 하신 게 맞다 — 코드가 아니라 **설계가 그렇게 돼 있다**.

정해야 할 것: **열을 숨길 것인가 / 가로 스크롤 + 첫 열 고정할 것인가.**
모든 원장에 걸리는 결정이라 화면 하나만 바꾸면 화면마다 달라진다.
(세로 헤더 고정은 이미 된다.)

## 5. 「효율적으로」 — 손으로 치지 않는 등록

사장님 지적: «계좌 등록 이런 거 효율적으로 해야 하는데».
지금 계좌·카드·CMS·단말기를 전부 손으로 친다. **그럴 필요가 없다** — 올리는 파일 안에 이미 다 있다.

```
자금 엑셀 업로드
  → 거래에서 계좌번호·cardLast4·cmsId·terminalId 수집
  → 마스터에 없는 값 발견 → 「110-234-567890 (기업) · 42건 — 등록할까요?」
  → 누르면 채널 생성 + 그 거래들이 한꺼번에 회사에 붙음
```

§1 의 해석기를 만들면 **자연히 따라오는 기능**이다. 둘은 같은 작업으로 묶는다.
