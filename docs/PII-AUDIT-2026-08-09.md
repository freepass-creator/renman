## 1. 리전 — 전부 서울로 맞춤

| 대상 | 감사 전 | 조치 | 지금 |
|---|---|---|---|
| Firestore | `asia-northeast3` | — | 서울 ✓ |
| Storage | `ASIA-NORTHEAST3` | — | 서울 ✓ |
| RTDB | `asia-southeast1`(싱가포르) | 참조 제거 | 미사용 · 설정에서 삭제 |
| Vercel 함수 | **`iad1`(미국 동부)** | `icn1` 로 변경 | 서울 ✓ |

**Vercel 함수가 제일 컸다.** OCR 업로드(계약서 스캔)·엔티티 저장·마이그레이션 API 가 전부 미국을 거치고 있었다.
계약서 스캔에는 주민등록번호가 인쇄돼 있으므로 개인정보 국외이전에 해당한다.
프로젝트 설정 + `vercel.json` 양쪽에 박아 프로젝트를 재생성해도 유지된다.

RTDB 는 **비어 있고 호출 코드도 없었다**(`getRtdb` 소비처 0). 안 쓰는 국외 저장 경로를 설정에
남겨 두면 언젠가 누가 쓴다 → `lib/firebase/client.ts` 에서 제거하고 환경변수도 삭제.
**남은 일: 싱가포르 RTDB 인스턴스 자체는 콘솔에 남아 있다(비어 있음). 삭제는 되돌릴 수 없어 보류.**

## 4. 이번에 막은 것

### 4-1. 규칙 (배포 완료)
- **claim 없는 계정 차단** — `tenantOK` 에 `companyId is string`.
  자가 가입 계정은 `myCompany()` 가 null 이라 companyId 없는 문서에서 `null == null` 로 통과했다.
  공개 API 키가 클라 번들에 있으므로 화면 없이도 계정 생성 가능 → 규칙이 유일한 경계였다.
  실측 노출 1건(`_conntest`). 구조적 원인은 `businessColl` 이 **제외 목록**이라는 것 → `_` 접두도 제외.
- **스토리지 원본 삭제는 본사만** — `allow write` 가 delete 까지 주고 있었다. 증빙 원본이 사라지면 감사 추적이 끊긴다.

### 4-2. 스토리지 버킷
- `publicAccessPrevention: inherited` → **`enforced`**.
  `uniformBucketLevelAccess:false` 라 객체 ACL 로 공개 전환이 가능한 상태였다(현재 공개 객체는 0).
- **수명주기 규칙 신설** — `firestore-managed/` 90일 후 자동 삭제.
  Firestore 백업 3세트(153객체)가 문서와 같은 버킷에 무기한 쌓이고 있었다. 백업에는 전체 PII 가 들어간다.

## 5. 남은 것 (판단 필요)

1. **보존기간 정책이 없다.** 계약·감사로그·문서 원본이 무기한 보관된다.
   PIPA 는 보유기간 경과 시 파기를 요구한다. 렌터카 계약은 계약종료 후 보존연한을 정하고
   그에 맞춘 파기 절차(소프트삭제 → 기간 경과 → 실제 파기)가 필요하다.
2. **싱가포르 RTDB 인스턴스 삭제** — 비어 있고 이제 아무것도 가리키지 않는다.
3. **프리뷰가 운영 Firestore 를 쓴다.** 프리뷰에서 저장하면 실데이터가 바뀐다.
   완전 분리하려면 별도 Firebase 프로젝트가 필요하다.
4. **GitHub 푸시 = 운영 자동배포.** 육안 확인 전에 나간다. 브랜치 분리 또는 자동배포 해제 검토.
