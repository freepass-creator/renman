# 커서 오더 목록 (오픈 준비 · 2026-07-31)

우선순위 순. 각 문서는 그대로 실행 가능한 «파일별 작업 지시»이며, 문서 끝의 **공통 규약**을 반드시 지켜야 한다.

| 순 | 오더 | 등급 | 왜 |
|---|---|---|---|
| 1 | [계정 관리 콘솔](CURSOR-ORDER-auth-console.md) | **필수** | 퇴사자 계정 회수·비번리셋·권한승강을 ERP 안에서 못 한다. Firebase 콘솔 직접 접근 = 관리자 1인 의존 |
| 2 | [화면 목록 → 엑셀 내보내기](CURSOR-ORDER-excel-export.md) | 높음 | 대표 보고·세무사 전달·보험 갱신 명단을 직원이 화면 보며 손타이핑 중. 파생값(미수금·연체일)은 덤프에도 없어 미수 명단을 아예 못 만듦 |
| 3 | [회차별 청구 스케줄 원장 + 문자 진입점](CURSOR-ORDER-schedule-ledger.md) | 높음 | «이번 달 청구 예정 몇 건·얼마»를 차량 하나하나 열어야 안다. 템플릿 13종인데 발송 버튼이 미수관리 1곳뿐이라 예방 발송 불가 |
| 4 | [자산·계약 입력 공백 3건](CURSOR-ORDER-asset-gaps.md) | 높음 | 자동차세 만기 사각지대(체납=번호판 영치) · 매각가 입력 폼 없음(처분손익이 계산되고도 안 보임) · 계약번호가 비면 내용증명에 «—»로 인쇄 |

## 순서를 지켜야 하는 이유

2번(엑셀)의 **선결 작업**(`ExcelSheet`가 보이는 rows·cols를 내보내게 + `LedgerFrame` cols `useMemo` 고정)은
3번 회차 원장의 엑셀 내보내기도 그대로 쓴다. 2번을 먼저 끝내라.

1번은 다른 셋과 파일이 겹치지 않으므로 병행 가능하다.
