# 웹 데이터센터 중심 ERP 설계 기준

## 제품 정의

이 ERP의 시작점은 직원의 원장 입력이 아니라 회사에서 발생한 원본 자료다.

사용자는 자료의 종류나 저장될 메뉴를 먼저 판단하지 않고 파일·사진·엑셀·메모를 데이터센터에 넣는다. 시스템은 자료를 보존한 뒤 판독·분류·중복검사·기존 원장 연결을 수행하고, 확정 가능한 데이터는 해당 원장에 반영한다. 확정할 수 없는 건은 버리지 않고 검토대기 또는 미처리 업무로 남긴다. 날짜·금액·상태를 해석해 도래·경과·불일치·미수·누락을 리스크와 업무로 제시한다.

```text
원본 투입
  → 원본 영구보관·해시 중복검사
  → 문서 종류 자동판정
  → OCR/표/거래내역 구조화
  → 회사·차량·계약·고객·거래 자동연결
  → 신뢰도별 자동반영 / 확인요청 / 미분류
  → 원장·서류함·이력 동시 배치
  → 누락·미처리·기한·금액 불일치 판정
  → 리스크·업무·알림 생성
  → 처리 증거와 감사이력 보존
```

## 웹 우선 사용자 흐름

1. 직원은 데이터센터의 하나의 드롭존에 여러 자료를 섞어 넣는다.
2. 시스템은 각 파일을 `분석중 / 자동반영 / 확인필요 / 미분류 / 중복`으로 구분한다.
3. 직원은 전체 내용을 다시 입력하지 않고 시스템이 제시한 연결과 충돌 항목만 확인한다.
4. 반영 후 각 자료는 차량·계약·고객·자금 등 해당 원장과 서류보관함에서 함께 조회된다.
5. 처리되지 않은 자료와 파생 업무는 사라지지 않고 업무·리스크 화면의 큐로 이어진다.
6. 일정 도래, 기한 경과, 미수, 서류 누락, 데이터 불일치가 담당자에게 우선순위로 제시된다.

## 끊김 없는 업무 원칙

모든 입력은 완성된 서식이 아니라 이어서 처리할 수 있는 `업무 객체`를 먼저 만든다.

- 메모 한 줄, 파일 한 장, 사진 한 장 중 하나만 있어도 즉시 건을 생성한다.
- 최초 정보가 부족하면 `미분류 + 미처리 + 미배정`으로 저장한다. 필수항목 부족을 이유로 원본 입력 자체를 거부하지 않는다.
- 분류, 실행상태, 담당상태는 서로 다른 축이다. `미분류`는 자료의 성격, `미처리`는 실행 여부, `미배정`은 담당자 여부다.
- 같은 건에 파일·메모·대상·기한·담당자를 나중에 계속 추가할 수 있어야 한다.
- 자동분석이나 사람이 차량·계약·고객을 연결해도 기존 건을 새로 만들지 않고 같은 건을 보강한다.
- 분류 전후, 담당 변경, 상태 변경, 첨부 추가, 원장 반영 이력을 시간순으로 보존한다.
- 미처리 건은 목록에서 사라지지 않으며 담당·기한·우선순위가 비어 있으면 그 자체를 보완 필요 상태로 표시한다.
- 완료 후 새 자료나 불일치가 발견되면 같은 건을 재개방하거나 연결된 후속 업무를 만든다.

```text
파일/메모 투입
  → 업무 ID 즉시 발급
  → 미분류·미처리·미배정 저장
  → OCR/자동분류 결과를 같은 업무에 추가
  → 차량·계약·고객 연결
  → 담당·기한·우선순위 보완
  → 작업 진행·완료
  → 원본과 전 변경이력 유지
```

업무 생성의 최소 조건은 `회사 + 파일 또는 내용`이다. 차량번호, 업무분류, 제목, 담당자, 기한은 최초 생성의 필수값이 아니라 이후 보완 가능한 값이다.

## 판정 결과 규격

모든 투입 건은 아래 중 하나의 상태를 가져야 하며 파일이 단순히 저장된 채 사라지면 안 된다.

- `분석중`: 원본 저장 완료, 판독 진행 중
- `자동반영`: 문서 종류와 대상 연결이 모두 고신뢰이며 원장 반영 완료
- `확인필요`: 일부 값의 충돌 또는 복수 연결 후보가 있어 사람의 한 번 확인이 필요
- `미분류`: 문서 종류 또는 대상 식별 실패. 미처리 업무로 노출
- `중복`: 동일 원본 해시 또는 동일 고유번호 자료가 이미 존재
- `오류`: 판독/저장 실패. 재시도 가능하고 원본은 보존
- `처리완료`: 확인·보정·연결까지 끝나 후속 위험이 해소됨

## 자동화 신뢰도 원칙

- 고신뢰: 고유번호와 핵심값이 기존 데이터와 일치하면 자동반영한다.
- 중신뢰: 가장 유력한 대상과 근거를 제시하고 확인 한 번으로 반영한다.
- 저신뢰: 임의로 원장을 만들지 않고 미분류 큐에 둔다.
- 값 충돌: 기존 값을 덮지 않고 원본값/현재값/추천값을 비교한다.
- 모든 자동변경은 원본 파일, 추출값, 판단근거, 변경 전후, 수행시각을 감사이력에 남긴다.

## 현재 코드에서 재사용할 기반

- 원장 엔티티: `vehicle, contract, customer, insurance, bank_account, lease, bank_tx, card_tx`
- 이벤트 엔티티: `work_item, history, penalty, inbox`
- 통합 저장: `saveIntake`의 정규화·원자 이벤트·부수효과
- 기존 자동연결: 계약→차량, 보험→차량 요약, 입출금/CMS→수납
- 일정 판정: 계약 반납, 검사, 보험, 과태료, 자동차세
- 리스크 판정: 미수, 자금 미분류, 서류/원장 불일치, 만기·경과
- OCR 기반: 등록증, 면허증, 보험증권, 계약서, 과태료, 견적서

## 현재 구조의 핵심 결손

1. 업로드 전에 사용자가 엔티티를 선택해야 한다.
2. 일반 수집함 업로드는 원본 보관만 하고 자동 OCR·문서분류를 수행하지 않는다.
3. 자료 한 건이 여러 원장·이력·증빙에 동시에 반영되는 처리계획이 없다.
4. 자동반영/확인필요/미분류/중복/오류의 공통 처리상태와 판단근거가 없다.
5. OCR 지원 문서가 제한적이고 매입·세금·금융·사고·검사·반납 자료가 하나의 분류기로 연결되지 않는다.
6. 파생된 미처리 업무의 생성·해소·재개방 수명주기가 통합되어 있지 않다.

## 웹 구현 순서

1. 데이터센터 첫 화면을 통합 드롭존 + 처리현황 큐로 변경한다.
2. 원본 레코드에 파일 해시, MIME, 추정 문서종류, 신뢰도, 처리상태, 연결 후보, 오류, 추출 원문을 저장한다.
3. 문서 라우터를 만들고 기존 OCR 프로필과 엔티티 매핑을 연결한다.
4. 분석 결과를 원장별 변경계획으로 만든 뒤 고신뢰 자동반영과 확인필요를 분리한다.
5. 미분류·충돌·필수서류 누락을 업무/리스크 큐와 연결한다.
6. 매입·세금·금융·정비·사고·검사·인도/반납 순으로 문서 프로필을 확장한다.
7. 처리량, 자동반영률, 확인대기, 오류, 경과업무를 운영 대시보드에서 측정한다.

## 출시 전 필수 시뮬레이션

- 여러 회사의 등록증·계약서·보험증권·고지서·거래내역을 섞어 한 번에 투입한다.
- 동일 파일 재투입, 같은 차량의 갱신증권, 잘못 읽힌 차량번호, 복수 계약기간을 검증한다.
- 자동반영된 값이 실제 자산·계약·자금·업무·리스크 화면에 동시에 나타나는지 확인한다.
- 미분류 건이 업무 큐에 남고, 보정 후 원장 연결과 함께 해소되는지 확인한다.
- 기한 도래/경과 날짜를 이동해 알림과 우선순위가 예상대로 변하는지 확인한다.
- 원본 삭제·재업로드·보정 시 감사이력과 과거 OCR 스냅샷이 유지되는지 확인한다.
