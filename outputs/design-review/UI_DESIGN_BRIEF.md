# 렌터카매니저 UI/UX 재설계 브리프

## 요청

현재 구현을 미화하는 수준이 아니라, 기능과 원자데이터만 유지한 채 화면 체계를 다시 설계한다.
단, 이번 검토에서는 코드를 수정하지 말고 하나의 명확한 디자인 방향과 구현 규격을 제안한다.

## 제품 정의

- 외부 렌터카 업체에도 판매하는 멀티테넌트 B2B ERP다.
- 사고대차, 장기렌트, 월렌트, 일렌트에 공통으로 적용되어야 한다.
- 회사별 CI/BI를 넣을 수 있어야 하며 특정 제품 브랜드를 강제하지 않는다.
- 직원의 주 업무는 원장을 직접 타이핑하는 것이 아니라 계약서, 보험증권, 등록증, 계좌 엑셀, 통화녹음 등 원본 자료를 올리는 것이다.
- AI가 원본에서 원자데이터를 추출하고 계약·차량·수납·자금에 연결한다.
- ERP의 첫 화면은 전체 데이터를 늘어놓는 곳이 아니라 누락, 불일치, 연체, 미배차, 미매칭 등 지금 처리할 예외를 보여주는 곳이다.

## 확정된 최상위 정보구조

상단에는 세 영역만 둔다.

1. 업무조회: 검색과 지금 처리할 업무
2. 데이터센터: 필요할 때 차량·계약·수납·자금 원자데이터 조회
3. 자료올리기: 파일 기반 업무 시작

기본적으로 사이드바는 사용하지 않는다. 전역 메뉴와 페이지 내부 탭을 중복시키지 않는다.

## 가장 중요한 화면: 업무조회

### 반드시 포함할 것

- 차량번호, 고객, 계약번호를 찾는 단일 검색창
- 검색창과 같은 도구영역 안의 필터
- 아주 작은 운영 요약: 전체 업무 수, 가동률, 미수 금액/미수율
- 처리할 업무 목록
- 책임 구분: 우리 처리 / 고객 이행
- 업무 분류: 미수·수납 / 계약·보험 / 차량 / 자료 / 자금 / 기타
- 상태: 연체, 기한경과, 오늘, 임박, 확인필요, 진행, 대기 등
- 담당자와 미배정
- 긴급순, 담당자순, 분류순 정렬
- 행을 누르면 차량 상세 또는 해당 처리 화면으로 이동

### 데스크톱 행의 현재 데이터 계약

`우선순위 표시 | 구분 | 상태 | 처리할 일 | 대상 | 문제·근거 | 담당자 | 이동`

표현 예:

- `고객·미수 | 연체 | 납부 요청 | 123가4567 · 홍길동 | 2회 · 1,200,000원 | 성유민`
- `우리·계약 | 확인필요 | 계약·보험 확인 | 456나7890 · 김철수 | 계약 21세 / 보험 26세 불일치 | 미배정`
- `우리·자료 | 대기 | 등록증 확인 | 789다0123 | 계약서 등록, 등록증 미첨부 | 강지수`

### 모바일

- 데스크톱 표를 가로 스크롤로 축소하지 않는다.
- 한 업무를 `상태·분류 / 처리할 일 / 대상 / 문제·근거 / 담당자` 순서의 스캔 가능한 행 또는 목록으로 재배치한다.
- 검색, 필터, 업무 확인, 자료 업로드, 차량 상세 확인까지 대부분 가능해야 한다.
- 터치 영역 44px 이상, 본문 14px 이상을 기본으로 본다.

## 데이터센터

- 내부 탭: 차량 / 계약 / 수납 / 자금
- 엑셀처럼 직관적이고 조밀한 표이되, 브라우저 ERP의 검색·필터·정렬·고정헤더·상세 이동을 제공한다.
- 기본 목록에는 현재 운영에 필요한 데이터만 보이고 매각완료 등 과거 자료는 필터로 조회한다.
- 행을 누르면 차량 또는 계약 상세로 이동한다.
- 대형 지표 카드, 홍보성 설명문, 장식용 빈 공간을 두지 않는다.

## 자료올리기

- 사용자는 먼저 복잡한 원장 분류를 채우지 않는다.
- 계약서, 보험증권, 자동차등록증, 계좌내역, 통화녹음 등의 원본을 올리고 AI 분석 결과와 연결 상태만 확인한다.
- 업로드 대기 / 분석중 / 확인필요 / 반영완료 상태가 명확해야 한다.
- 업로드 후 생성되거나 해소된 업무가 업무조회에 반영된다.

## 차량 상세

- 현재 상태와 다음 행동이 먼저 보인다.
- 차량 기본정보, 활성계약, 미수 건수·금액, 보험, 검사, 휴차일을 요약한다.
- 계약, 수납, 통화, 정비, 사고, 보험, 과태료, 문서, 자금 이력을 시간순으로 연결한다.
- 한 번 입력하는 기준정보와 계속 쌓이는 운영이력을 분리한다.

## 시각 원칙

- 2026년형 정돈된 B2B 운영 콘솔/리포트 느낌.
- 유치원 숙제 같은 큰 숫자 카드와 색색의 박스는 금지.
- 과도한 둥근 카드, 캡슐형 버튼, 떠 있는 버튼, 장식적 그림자는 금지.
- 격식 있고 차분한 중립색 기본 테마. 회사별 accent 색상만 교체 가능하게 한다.
- 큰 모서리 6px, 작은 모서리 4px 정도의 절제된 규격.
- 선, 여백, 타이포그래피로 위계를 만들고 색은 상태와 위험 표현에만 제한한다.
- 본문은 14px 전후, 표 보조정보는 12px 이하로 내려가더라도 핵심 텍스트는 작아지지 않게 한다.
- 버튼은 대상과 행동이 분명한 위치에만 둔다. 조회 화면에 자료올리기 같은 쓰기 CTA를 억지로 넣지 않는다.
- 설명형 hero/marketing copy를 넣지 않는다.
- 검색은 한 곳만 강하게 보이게 한다.

## 최신 디자인 시스템에서 반영할 근거

- 검색은 목록과 직접 연결되는 위치에 두고 입력 즉시 결과를 좁힌다.
- 표의 툴바에 검색, 필터, 표시설정, 실제 주 행동을 모은다.
- 표는 정렬·고정헤더·점진적 상세 공개를 지원하되 스프레드시트를 흉내 내는 데 매몰되지 않는다.
- 디자인 토큰과 작은 재사용 primitive로 페이지 간 규격을 통일한다.
- AI가 만든 값은 필요할 때 근거와 신뢰도를 설명할 수 있어야 한다.

## 산출물 요청

다음 순서로 답한다.

1. 현재 구조에서 가장 큰 UX 문제 5개
2. 확정할 단일 디자인 콘셉트 이름과 한 문장 정의
3. 데스크톱 업무조회 화면의 정확한 세로 순서와 각 영역 높이/밀도
4. 모바일 업무조회 화면의 정확한 재배치
5. 상단 내비게이션, 검색/필터 툴바, 업무 행, 상태표시, 버튼의 컴포넌트 규격
6. 데이터센터, 자료올리기, 차량 상세가 같은 디자인 언어를 공유하는 방법
7. 색상, 타이포, 간격, 모서리, 선, 그림자의 디자인 토큰 초안
8. 현재 코드에서 무엇을 유지하고 무엇을 갈아엎을지 파일 단위 구현 순서
9. 피해야 할 안티패턴

여러 시안이나 취향 질문을 내지 말고, 근거를 설명한 하나의 완성도 높은 방향을 선택한다.
